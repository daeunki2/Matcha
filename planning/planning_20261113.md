# Matcha Development Milestones

| Milestone | Core Features | Related Bonuses | Completion Criteria |
|---|---|---|---|
| M1 — Authentication | Registration, email verification and resend, login, current user retrieval, token refresh, logout, password reset | Google authentication and account linking | Authentication flows work through the frontend, including expired tokens and error cases |
| M2 — Profiles & User Interactions | Profile editing, reusable tags, up to five photos, profile picture selection, GPS consent and manual location, profile views, visit history, likes/unlikes, mutual connections, blocking, reporting, fame rating | Drag-and-drop photo upload, cropping, rotation, filters | Users can complete profiles and interact with others; permissions and relationship rules are enforced by the backend |
| M3 — Recommendations & Search | Recommendations based on preferences, proximity, shared tags and fame; advanced search, sorting, filtering, pagination | Interactive user map | Results respect preferences, location and blocking rules; required sorting and filtering work |
| M4 — Chat & Notifications | Chat between connected users, required notifications, unread indicators accessible from any page, online status and last connection time | Audio/video calls | Messages and notifications arrive within 10 seconds; unliking or blocking prevents further chat as required |
| M5 — Date Scheduling | Date proposals, acceptance, changes, cancellation and schedule viewing | This milestone is a bonus feature | Connected users can arrange and manage dates |
| M6 — Final Validation | At least 500 distinct profiles, security checks, input and upload validation, graceful error handling, mobile layout, Firefox/Chrome compatibility, setup documentation | Integration testing of all implemented bonuses | All mandatory requirements work correctly and the project can be reproduced from the repository |

## Working Rules

- Agree on API contracts before implementing each feature.
- Integrate and test the frontend and backend at each milestone.
- Include related bonuses after the corresponding core flow works.
- Apply security and validation throughout development.
- Work on individual branches and use pull requests into `test`.
- Bonus features are evaluated only if all mandatory requirements are fully satisfied.

# M2 — Discussion Topics

| Topic | Points to Discuss |
|---|---|
| Profile information | Input formats and required fields for gender, preferences, biography, age and tags. Define when a profile is complete. |
| Editing information | How users update their names, email and profile. Decide how to verify a new email address before applying the change. |
| Photos | Manage up to five photos, choose a profile picture and define deletion rules. Divide responsibilities for drag-and-drop uploads and photo editing bonuses. |
| Location | GPS consent, manual city entry, location updates and what location information other users can see. |
| Profile viewing | Public information, visit history, visitor lists, online status and last connection time. |
| User interactions | Likes, unlikes, mutual connections, received likes, blocking, reporting and fame rating criteria. |
| APIs & collaboration | Required endpoints and request/response formats, frontend/backend responsibilities, PR workflow and integration testing schedule. |
